# MomaDefense — 마크 운빨 디펜스

Paper **26.3 build 19 alpha**, Java **25** 기반 개인 전장 디펜스입니다. 기본 명령은 **/mud**, 포탑 조작은 **좌클릭**입니다. 클라이언트 모드는 필요하지 않습니다.

**100라운드 자동 웨이브, 보스, 처치 수입, 소환·판매·재배치, 승패 판정**이 구현되어 있습니다. 같은 Java 코어를 실행하는 독립 시뮬레이터와 브라우저 리플레이도 포함합니다.

## 설치와 시작

~~~powershell
mvn -B -ntp clean verify
~~~

생성된 target/moma-defense-0.3.0.jar를 Paper 서버의 plugins 폴더에 넣고 재시작합니다. 서버/API는 26.3.build.19-alpha로 고정했으며 실험 빌드입니다. Bukkit/Spigot/Folia는 지원하지 않습니다.

[Paper build 19 메타데이터](https://fill.papermc.io/v3/projects/paper/versions/26.3/builds/19) · 서버 파일 paper-26.3-19.jar · SHA-256 f623c073913db7f21c6338eef22a00b19a8d87c1ef3115c2060d2382b90f4650

관리자는 전장을 생성하고 플레이어는 참가합니다. 참가 후 **15초 준비 시간**이 지나면 적이 자동으로 나옵니다.

~~~text
/mud create arena1
/mud join arena1
~~~

| 조작 | 동작 |
|---|---|
| F 또는 재지정한 보조 손 교환 키 | 소환·판매 GUI |
| 자신의 포탑 좌클릭 | 선택 또는 선택 변경 |
| 빈 파란 배치 칸 좌클릭 | 즉시 이동 후 선택 해제 |
| 경로·점유 칸·전장 밖 좌클릭 | 이동 거절, 기존 선택 유지 |
| 우클릭 | 포탑 조작 없음 |
| /mud leave | 게임 종료, 이전 위치·게임 모드 복구 |

기본 5×5 배치 칸을 바깥줄 북서쪽부터 시계 방향으로 채웁니다. 판매한 빈 칸을 다시 사용합니다. 조작 사거리는 24블록, 선택 효과는 소유자에게만 보입니다. 이동해도 공격 대기시간·연속 공격 상태가 유지됩니다. GUI는 일반 좌클릭만 받으며 구매·판매 간격은 최소 5틱입니다.

## 100라운드와 적

| 항목 | 규칙 |
|---|---|
| 준비 | 15초, 시작 100원 |
| 라운드 | 1~100, 각 30초 |
| 출현 | 매 라운드 첫 22.5초에 분산 출현 |
| 적 한도 | 살아 있는 적 100마리에 도달하면 패배 |
| 보스 | 10·20·…·100라운드, 라운드 시작 15초 후 출현 |
| 일반 적 보상 | 6원 |
| 보스 보상 | 30원 |
| 승리 | 100라운드의 마지막 출현까지 끝나고 남은 적 0마리 |
| 최종 정리 | 100라운드 시간 종료 후 추가 60초, 남은 적이 있으면 패배 |

라운드가 바뀌어도 적은 사라지지 않고 붉은 순환 경로를 계속 돕니다. 한 게임의 최대 길이는 **51분 15초**입니다. 보스 별도 시간제한은 없고 전체 적 한도·최종 정리 시간을 따릅니다.

| 적 | 기본 체력 대비 | 속도(블록/초) | 역할 |
|---|---:|---:|---|
| 좀비 | 1.00 | 2.0 | 보병 |
| 허스크 | 1.65 | 1.5 | 튼튼한 느린 적 |
| 드라운드 | 1.20 | 1.8 | 혼성 보병 |
| 거미 | 0.65 | 3.5 | 빠른 적 |
| 슬라임 | 0.55 | 2.5 | 군집 |
| 마그마 큐브 | 1.35 | 2.1 | 튼튼한 혼성 적 |

- 5라운드 주기: 보병 → 돌격 → 군집 → 중장갑 → 혼성. 중장갑은 체력이 높은 편성이며 별도의 방어력 스탯은 없습니다.
- 기본 적 수: 12 + 2 × floor((라운드−1)/10). 군집은 +8, 중장갑은 −3. 보스는 별도 1마리.
- 기본 체력: 24 × 1.055^(라운드−1) × 3.05 × 후반 배율. 후반 배율은 1 + 19 × max(0, (라운드−60)/40)²이며 1~60라운드는 1배, 100라운드는 20배입니다. 보스 체력은 기본 체력 × (15 + 라운드/5), 속도 1.2.
- 실제 100개 라운드별 편성·체력은 [waves.json](docs/simulation/waves.json)에 있습니다.
- 공유 규칙은 src/main/resources/campaign.properties, 편성 공식은 WaveSchedule입니다. 수정 후 다시 빌드하고 시뮬레이션을 재실행해야 검증 결과를 적용할 수 있습니다.

## 아군·등급·경제

진영은 ENEMY/DEFENDER, 소유권·전장·체력·재화는 서버 상태로 판정합니다. 적과 아군 외형은 겹치지 않으며 자연 AI·접촉 충돌·연소·분열·변신·드롭은 게임에 개입하지 않습니다. 아군은 무적 고정 포탑이고 플레이어가 직접 적을 공격할 수 없습니다.

| 타입 | 아군 4종 | 전설 이상 자동 특수효과 |
|---|---|---|
| 근거리 단일 | 늑대·북극곰·판다·토끼 | 동일 대상 연속 공격 강화 |
| 근거리 광역 | 철골렘·호글린·염소·파괴수 | 감속 |
| 원거리 단일 | 스켈레톤·스트레이·보그드·피글린 | 보스 추가 피해 |
| 원거리 준광역 | 마녀·라마·눈골렘·가디언 | 중심 대상 추가 피해 |
| 원거리 대광역 | 블레이즈·가스트·위더 스켈레톤·워든 | 반경 증가 |
| 원거리 다중 | 소환사·셜커·알레이·벡스 | 동시 대상 수 증가 |

24종 균등 추첨과 등급 추첨은 독립적입니다. 모든 등급에서 타입이 유지됩니다. 가장 멀리 진행한 적을 우선하고 다중 공격은 같은 적을 중복 타격하지 않습니다. 범위 공격은 중심 주변 적을, 근거리 광역은 120도 부채꼴을 공격합니다. 감속은 가장 강한 활성 효과만 적용합니다.

**1회 소환 10원**. 확률·판매 규칙은 기존 합의와 동일합니다.

| 등급 | 확률 | 판매가 |
|---|---:|---:|
| 일반 | 50.001% | 3 |
| 레어 | 33.1% | 6 |
| 고대 | 10.2% | 9 |
| 유물 | 5.1% | 16 |
| 서사 | 0.8% | 30 |
| 전설 | 0.5% | 불가 |
| 에픽 | 0.2% | 불가 |
| 신화 | 0.08% | 불가 |
| 태초 | 0.019% | 불가 |

전설 이상 획득 시 전체 방송합니다. 천장·합성·교환은 없습니다. 재화 부족·빈 칸 없음·엔티티 생성 실패는 재화를 소모하지 않습니다. 전설 이상이 25칸을 모두 채우면 더 소환할 수 없습니다.

## 시뮬레이션과 밸런스

[검증 보고서](docs/simulation/REPORT.md) · [태초 2개 + 신화 7개 클리어 리플레이](docs/simulation/example-clear/replay.html)

최종 별도 시드 **20,000회 중 167회, 0.835%**가 클리어했습니다. 95% 신뢰구간은 **0.718–0.971%**입니다. **모든 클리어가 태초 2개 이상**이었고, 별도의 **태초 1개 제한 실험 10,000회는 클리어 0회**였습니다. 태초 2개 + 신화 4개 이상 조합에서는 203회 중 7회 클리어했습니다. 자동 배치 비교와 전체 편성별 결과는 검증 보고서에 있습니다.

기존의 태초 1개 클리어 문제를 상위 등급 격차와 후반 적 체력으로 조정했습니다. 승패 코드에 태초 개수 검사는 없고 전투력으로 결과가 결정됩니다. 실제 사람의 모든 전략에 대한 불가능성 증명은 아니지만, 최종 검증에서 태초 2개 미만 클리어는 관측되지 않았습니다. 태초 1개 제한은 시뮬레이터에서 추가 태초를 같은 종의 신화로 낮추는 실험으로 실제 서버의 뽑기 규칙은 그대로입니다.

| 등급 | 이전 피해 배율 | 현재 피해 배율 | 바로 아래 등급 대비 |
|---|---:|---:|---:|
| 전설 | 6 | 8 | 서사의 2배 |
| 에픽 | 9 | 24 | 전설의 3배 |
| 신화 | 40 | 120 | 에픽의 5배 |
| 태초 | 80 | 2400 | 신화의 20배 |

확률·판매가·사거리·공격속도·타입은 유지했습니다. 근거리 단일의 연속 타격 계수는 0.12에서 0.06으로 조정해 기본 근접 보정과 중첩된 태초 단독 캐리 성능을 줄였습니다. 같은 시드 100124에서 태초 2개·신화 7개는 승리, 두 번째 태초를 신화로 낮춘 태초 1개·신화 8개는 패배합니다.

근거리 단일·다중 공격을 보정하고 종별 약점도 검사했습니다. 라마·눈골렘·위더 스켈레톤·보그드·알레이에 보정을 적용했습니다. 여전히 레어 블레이즈와 신화 라마는 두 가지 고정 벤치마크에서 타입 중앙값 대비 낮아 후속 관찰 대상으로 보고서에 남겼습니다.

~~~powershell
mvn -B -ntp compile
java -Xmx2g -cp target/classes dev.moma.sim.SimulatorMain 20000 3100000 3.05 target/validation BALANCED 20
java -Xmx2g -cp target/classes dev.moma.sim.SimulatorMain 10000 3500000 3.05 target/stress BALANCED 20 1
java -Xmx2g -cp target/classes dev.moma.sim.SimulatorMain 1 100124 3.05 target/example BALANCED 20
java -cp target/classes dev.moma.sim.RoleBenchmarkMain target/roles.jsonl
java -cp target/classes dev.moma.sim.WaveExportMain target/waves.json
~~~

각 실행은 summary.json, runs.jsonl, 시드별 trace JSONL, 독립 실행 가능한 replay.html을 생성합니다. 같은 시드는 같은 결과를 냅니다. 브라우저에서 replay.html을 열어 재생·배속·타임라인 탐색을 사용할 수 있습니다. 서버 없이 실행하며 외부 서비스나 Minecraft 접속이 필요하지 않습니다.

시뮬레이터는 20TPS의 실제 코어를 끝까지 실행합니다. 평균 DPS로 승패를 근사하지 않습니다. 판매·재배치는 실제 Arena API를 사용하며 미래 뽑기를 보지 않습니다. 사람의 조작 지연·네트워크·서버 렉은 모델에 없습니다.

## 명령과 운영

| 명령 | 권한 | 설명 |
|---|---|---|
| /mud list | moma.play | 전장 목록 |
| /mud join <이름> | moma.play | 개인 전장 참가, 100라운드 시작 |
| /mud leave | 없음 | 게임 종료 |
| /mud create <이름> | moma.admin | 5×5 전장 생성 |
| /mud spawn <종> [수] [boss] | moma.admin | 보상 없는 개발용 적 추가 |
| /mud coins <금액> | moma.admin | 개발용 재화 지급 |

명령은 /moma에서 /mud로 변경했고 기존 권한 노드 moma.play/moma.admin은 유지합니다. 플레이 권한은 기본 허용, 관리자 권한은 기본 OP입니다. 관리자 개입 명령을 사용한 판은 결과에 표시합니다.

전장은 moma_arenas 월드에 128블록 간격으로 생성되며 기존 블록을 덮어쓰지 않습니다. 이전 5×5 전장은 재사용할 수 있습니다. 다른 크기는 새 전장을 만들어야 합니다. 이전 개발용 config.yml은 더 이상 읽지 않습니다. 정식 캠페인은 패키지에 포함된 campaign.properties를 사용합니다.

전장 목록은 plugins/MomaDefense/arenas.yml에 저장됩니다. 진행 중 라운드·유닛·재화는 메모리에만 있으며 퇴장·접속 종료·서버 종료 시 정리됩니다. 정상 종료 시 이전 위치·게임 모드를 복구합니다. 재접속 이어하기와 크래시 복구는 지원하지 않습니다.

## 검증

- dev.moma.core: 확률·소유권·경제·전투·웨이브·승패. Paper 의존성이 없습니다.
- dev.moma.paper: 명령·엔티티·GUI·입력·게임 세션. 모든 상태 변경은 서버 메인 스레드에서 실행합니다.
- dev.moma.sim: 같은 코어의 자동 플레이·대량 검증·타입 벤치마크·리플레이 생성.
- mvn clean verify: 기존 동작, 웨이브 경계, 정확한 승패, 시드 재현성, 소환·판매·이동의 합법성 검증.
- scripts/summarize_simulation.py: 표준 Python만으로 측정 데이터의 보고서를 재생성합니다.
- scripts/check_replay.py: 별도 Playwright와 Edge를 사용해 데스크톱·모바일·재생·자바스크립트 오류를 검사합니다.

실제 Paper 서버와 접속 클라이언트의 플레이 검증은 별도입니다. [실서버 확인 목록](docs/manual-verification.md)을 제공합니다.
