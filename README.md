# MC Luck Defense — 마크 운빨 디펜스

Paper **26.3 build 26 alpha**, Java **25** 기반 개인 전장 디펜스입니다. 기본 명령은 **/mud**, 포탑 조작은 **좌클릭**입니다. 클라이언트 모드는 필요하지 않습니다.

**무한 라운드, 자동합성, 최고 라운드 TOP 10, 보스, 처치 수입, 소환·판매·재배치**를 지원합니다. 같은 Java 코어를 실행하는 독립 100라운드 비교 시뮬레이터와 브라우저 리플레이도 포함합니다. 현재 규칙은 [0.12.0 변경 사항](docs/release-0.12.0.md)을 참고하세요. 아래 과거 버전별 측정 결과는 합성·무한 모드의 클리어율을 의미하지 않습니다.

[기본 발전과제를 대신하는 전용 업적 50개](docs/achievements-draft.md)와 신화·태초 획득 전체 방송/효과음을 포함합니다.

## 설치와 시작

~~~powershell
mvn -B -ntp clean verify
~~~

생성된 target/mc-luck-defense-0.12.0.jar를 Paper 서버의 plugins 폴더에 넣고 재시작합니다. 기존 설치의 예약 업데이트는 plugins/update에 기존 JAR와 같은 파일명으로 넣습니다. Paper 플러그인 식별자는 MCLuckDefense, 콘솔 표시는 MC Luck Defense입니다. API는 26.3.build.26-alpha로 고정했으며 실험 빌드입니다. Bukkit/Spigot/Folia는 지원하지 않습니다.

0.5.0에서 업데이트할 때는 서버를 종료하고 기존 moma-defense JAR를 plugins 밖으로 옮긴 뒤, plugins/MomaDefense 폴더 이름을 plugins/MCLuckDefense로 변경하세요. 기존 arenas.yml과 전장 월드는 그대로 사용합니다. /mud 명령, 권한, 엔티티 데이터 키와 시드별 뽑기 결과는 유지합니다.

[Paper build 19 메타데이터](https://fill.papermc.io/v3/projects/paper/versions/26.3/builds/19) · 서버 파일 paper-26.3-19.jar · SHA-256 f623c073913db7f21c6338eef22a00b19a8d87c1ef3115c2060d2382b90f4650

관리자는 전장을 생성하고 플레이어는 참가합니다. 참가 후 **15초 준비 시간**이 지나면 적이 자동으로 나옵니다.

기본 **6×6 배치 칸 36개**이며 가장자리 20칸·안쪽 16칸입니다. **근접은 가장자리, 원거리는 안쪽부터** 채우고 선호 구역이 차면 나머지 빈 칸을 사용합니다. 각 줄은 북서쪽부터 시계 방향으로 배치합니다. 자동 배치가 OFF이면 기존 위치를 유지하고 판매한 빈 칸을 다시 사용합니다. ON이면 소환·판매 후 사거리와 공격력에 따라 전체 배치를 다시 계산하며 가득 찬 전장에서도 자리 교환이 가능합니다. 칸 간격은 3블록, 적 순환 경로는 84블록입니다. 조작 사거리는 24블록, 선택 효과는 소유자에게만 보입니다. 이동해도 공격 대기시간·연속 공격 상태가 유지됩니다. GUI는 일반 좌클릭만 받으며 수동 구매·판매 간격은 최소 1틱입니다.

## 자동판매·일괄구매·자동배치

F 메뉴에서 일반~신화 등급을 각각 **자동판매 ON/OFF**로 설정합니다. ON으로 바꾸면 보유 중인 해당 등급을 즉시 판매하고, 이후 같은 등급의 소환 결과도 판매가로 환급합니다. 태초만 판매할 수 없습니다. 강화 포탑은 투입된 개수만큼 판매가를 합산합니다. 새 게임에서는 모두 OFF로 시작합니다.

**일괄구매**는 10골드와 빈 칸이 있는 동안 반복 소환합니다. 자동판매 환급도 다음 구매에 사용합니다. 돈 또는 칸이 부족하면 종료하고, 진행 중 버튼을 다시 누르면 중지합니다. 종료된 구매가 처치 보상을 얻었다고 자동으로 다시 시작하지는 않습니다. 한 서버 틱당 최대 4회이며 게임 배속과 무관합니다.

**자동 배치 ON/OFF**도 F 메뉴에서 설정합니다. ON이면 적 경로 중 사거리 안에 들어오는 비율과 기본 초당 피해를 기준으로 칸을 배정합니다. 동일한 효율에서는 근접은 가장자리, 원거리는 안쪽을 선호하고 불필요한 이동을 줄입니다. 소환·판매를 묶어서 틱당 한 번 재계산하며 공격 대기시간·연속 공격 상태를 유지합니다. 직접 이동하려면 OFF로 전환하세요. 실제 적 밀도와 특수효과까지 고려한 최적 전투 결과를 보장하는 기능은 아닙니다.

0.9.0 밸런스 보고서는 기존 자동 플레이 정책의 결과입니다. 이 자동판매·일괄구매·자동배치 조합의 클리어율을 측정한 값으로 해석하지 않습니다.

## 무한 라운드와 적

로비의 네더포탈 블록에 몸이 닿으면 기존 게임 참가·관전 메뉴가 열립니다. 메뉴를 닫은 채 포탈 안에 머물러도 다시 열리지 않으며, 밖으로 나왔다가 다시 들어가면 열립니다. 포탈 우클릭 이벤트도 같은 메뉴로 연결합니다. 네더 이동은 계속 차단하고 게임 참가·관전은 메뉴에서 직접 선택합니다. F와 /mud도 그대로 사용할 수 있습니다.

| 항목 | 규칙 |
|---|---|
| 준비 | 1배 기준 15초, 시작 30골드 |
| 라운드 | 제한 없이 진행, 각 30초 |
| 출현 | 매 라운드 첫 22.5초에 분산 출현 |
| 적 한도 | 살아 있는 적 100마리에 도달하면 패배 |
| 보스 | 10라운드마다, 라운드 시작 15초 후 출현 |
| 일반 적 보상 | R1~20: 0.1골드, 이후 구간별 증가 |
| 보스 보상 | 해당 라운드 일반 적의 25배 |
| 101 이후 | 테마 반복, 체력 매 라운드 8% 증가, 적 수·보상 후반 수준 유지 |
| 최고 기록 | 도달 라운드 개인 최고값, 스폰 앞 TOP 10 |

라운드가 바뀌어도 적은 사라지지 않고 붉은 순환 경로를 계속 돕니다. 실제 게임에는 최종 승리·최종 정리 시간제한이 없으며 적 한도에 도달하면 패배합니다. 독립 비교 시뮬레이터는 기존 100라운드 종료 조건을 유지합니다.

| 적 | 기본 체력 대비 | 속도(블록/초) | 역할 |
|---|---:|---:|---|
| 좀비 | 1.00 | 2.0 | 보병 |
| 허스크 | 1.65 | 1.5 | 튼튼한 느린 적 |
| 드라운드 | 1.20 | 1.8 | 혼성 보병 |
| 거미 | 0.65 | 3.5 | 빠른 적 |
| 슬라임 | 0.55 | 2.5 | 군집 |
| 마그마 큐브 | 1.35 | 2.1 | 튼튼한 혼성 적 |

- 5라운드 주기: 보병 → 돌격 → 군집 → 중장갑 → 혼성. 중장갑은 체력이 높은 편성이며 별도의 방어력 스탯은 없습니다.
- 기본 적 수: 12 + 2 × floor((라운드−1)/10). 군집은 +8, 중장갑은 −3. 보스는 별도 1마리.
- 기본 체력: campaign.properties의 라운드별 health-curve 기준점을 기하 보간합니다. 정확한 기준점은 [검증 보고서](docs/simulation/economy-0.9.0/REPORT.md)에 있습니다. 보스 체력은 기본 체력 × (15 + 라운드/5) × boss-health-scale이며 최종 보스는 추가 1.75배입니다. 속도는 1.2입니다. 일반 적 압박과 보스 화력 요구량을 별도로 조정합니다.
- 실제 100개 라운드별 편성·체력은 [waves.json](docs/simulation/economy-0.9.0/waves.json)에 있습니다.
- 공유 규칙은 src/main/resources/campaign.properties, 편성 공식은 WaveSchedule입니다. 수정 후 다시 빌드하고 시뮬레이션을 재실행해야 검증 결과를 적용할 수 있습니다.

## 아군·등급·경제

진영은 ENEMY/DEFENDER, 소유권·전장·체력·재화는 서버 상태로 판정합니다. 적과 아군 외형은 겹치지 않으며 자연 AI·접촉 충돌·연소·분열·변신·드롭은 게임에 개입하지 않습니다. 아군은 무적 고정 포탑이고 플레이어가 직접 적을 공격할 수 없습니다.

| 타입 | 아군 4종 | 전설 이상 자동 특수효과 |
|---|---|---|
| 근거리 단일 | 늑대·북극곰·판다·토끼 | 동일 대상 연속 공격 강화 |
| 근거리 광역 | 철골렘·호글린·염소·파괴수 | 감속 |
| 원거리 단일 | 스켈레톤·스트레이·보그드·피글린 | 보스 추가 피해 |
| 원거리 준광역 | 마녀·라마·눈골렘·가디언 | 중심 대상 추가 피해 |
| 원거리 대광역 | 블레이즈·가스트·위더 스켈레톤·워든 | 반경 증가 |
| 원거리 다중 | 소환사·셜커·알레이·벡스 | 동시 대상 수 증가 |

24종 균등 추첨과 등급 추첨은 독립적입니다. 모든 등급에서 타입이 유지됩니다. 가장 멀리 진행한 적을 우선하고 다중 공격은 같은 적을 중복 타격하지 않습니다. 범위 공격은 중심 주변 적을, 근거리 광역은 120도 부채꼴을 공격합니다. 감속은 가장 강한 활성 효과만 적용합니다.

**1회 소환 10골드**. 확률·판매 규칙은 기존 합의와 동일합니다.

| 등급 | 확률 | 판매가 |
|---|---:|---:|
| 일반 | 50.001% | 3 |
| 레어 | 33.1% | 6 |
| 고대 | 10.2% | 9 |
| 유물 | 5.1% | 16 |
| 서사 | 0.8% | 30 |
| 전설 | 0.5% | 60 |
| 에픽 | 0.2% | 150 |
| 신화 | 0.08% | 375 |
| 태초 | 0.019% | 불가 |

신화·태초 획득 시 전체 방송과 소리를 보냅니다. 동일 종·등급 소환은 자동합성되며 강화마다 피해 +100%p, 5강마다 추가 +50%p가 적용됩니다. 합성 시 폭죽 효과를 표시합니다. 재화 부족·빈 칸 없음·엔티티 생성 실패는 재화를 소모하지 않습니다.

## 해시 기반 소환 난수

서버와 시뮬레이터 모두 **SHA-256 카운터 스트림(sha256-counter-v1)**으로 추첨합니다. 서버는 게임마다 SecureRandom으로 생성한 256비트 시드를 사용하며, 각 게임의 뽑기 스트림은 분리됩니다. 시뮬레이터는 재현 가능한 숫자 시드를 사용합니다.

해시의 32비트 값을 등급 100,000구간과 종 24구간으로 바꿀 때 **거부 샘플링**을 적용해 나머지 연산 편향을 제거합니다. 등급과 종은 별도 난수를 사용하며 확률표는 그대로입니다. java.util.Random.nextInt(bound)도 단순 나머지 편향은 피하므로, 기존 추첨의 편향이 검출됐다는 뜻은 아닙니다. 48비트 LCG 대신 명시적인 해시 알고리즘을 사용하도록 변경했습니다.

알고리즘이 바뀌어 이전 숫자 시드의 결과는 달라집니다. 결과 파일에 알고리즘 식별자를 기록하며 리플레이와 밸런스 검증을 모두 새 난수로 재생성했습니다. 독립 Python 해시 벡터·구간 경계 테스트를 통과했고, 240만 회 추첨에서는 태초 461회(기대값 456회)를 관측했습니다. [추첨 감사 원본](docs/simulation/random-audit.json)에 종·등급별 수치가 있습니다.

## 시뮬레이션과 밸런스

[30골드 시작 밸런스 보고서](docs/simulation/economy-0.9.0/REPORT.md) · [태초 2개 + 신화 7개 클리어 리플레이](docs/simulation/economy-0.9.0/example-clear/replay.html)

0.9.0은 시작 30골드, R1~20 일반 적 처치 보상 0.1골드로 재설계했습니다. 일반~서사 피해 배율은 1.75/2.5/3.5/5/7로 상향하고 블레이즈 기본 피해는 10→12로 보정했습니다. 태초 피해 배율은 4800, 신화는 120으로 격차를 벌리면서 최종 구간 적 체력도 함께 조정했습니다. 소환 확률·비용·판매가는 유지합니다.

라운드 생존 목표는 R30 50%, R50 30%, R70 10%, R90 5%, 최종 클리어 약 1%입니다. 실제 측정값·신뢰구간·태초 1개 제한 실험과 타입 비교는 위 보고서에 있습니다. 이전 경제의 [0.8.2 이전 보고서](docs/simulation/REPORT.md)는 과거 기록이며 새 밸런스 결과로 사용하지 않습니다.

확률은 처음 시작한 모든 자동 플레이 판을 분모로 합니다. 자동 플레이어는 1배 게임 시간 기준 2틱마다 최대 한 번 거래·이동하고 미래 뽑기를 보지 않습니다. 빠른 자동 플레이의 결과이므로 실제 플레이어 전체의 상위 백분위를 의미하지 않습니다. 개별 배속에서 사람의 조작 시간은 별도 변수입니다.

```powershell
mvn -B -ntp compile
java -Xmx2g -cp target/classes dev.moma.sim.SimulatorMain 20000 9300000 1 target/validation BALANCED
java -Xmx2g -cp target/classes dev.moma.sim.SimulatorMain 10000 9700000 1 target/stress BALANCED 1
java -Xmx2g -cp target/classes dev.moma.sim.SimulatorMain 2000 9300000 1 target/auto-placement AUTO_PLACE
java -cp target/classes dev.moma.sim.SimulatorMain 1 100147 1 target/example BALANCED
java -cp target/classes dev.moma.sim.RoleBenchmarkMain target/roles.jsonl
java -cp target/classes dev.moma.sim.WaveExportMain target/waves.json
```

CLI 인수는 실행 수, 시작 시드, 체력 배율, 출력 폴더, 정책, 선택적 태초 제한, 체력 기준점 문자열, 보스 배율 순서입니다. summary.json에는 시작 골드·보상·등급 보정·자동 조작 간격을 함께 기록합니다. runs.jsonl과 시드별 trace, 독립 replay.html을 생성하며 소수 골드도 표시합니다.

## 26.3-mud 서버 최적화와 20세션 검증

[전용 서버 브랜치](https://github.com/Love0118/paper-pathetic-mobs-fork/tree/26.3-mud) · [성능 보고서와 원본](docs/performance/REPORT.md)

20개의 실제 TCP 클라이언트와 100라운드를 실행한 최종 결과는 **314.59 TPS, 평균 2.053ms, p95 3.828ms**였습니다. 모두 100라운드까지 완료했지만 3.125ms 예산을 넘긴 틱이 13.10%라서 **320 TPS 지속 유지는 미달**입니다. 아군 720·적 1,800을 계속 유지하는 밀집 부하에서는 공식 Paper+기존 플러그인 51.73 TPS → 전용 서버+최적화 플러그인 158.21 TPS였습니다. 호스트 변동과 측정 조건은 보고서를 참고하세요.

플러그인은 정지 포탑 teleport·목록 복사·중복 타격 이펙트를 줄이고 물리와 전용 월드 자연 스폰을 끕니다. 전용 서버가 있을 때만 명시적으로 표시된 MUD 엔티티의 연속 이동 경로를 사용합니다. 일반 Paper에서는 기존 이동으로 돌아갑니다. 전투·경제·뽑기 규칙은 유지됩니다.

전용 서버의 config/paper-global.yml에서 아래 세 옵션을 켜고 재시작합니다. 기본값은 모두 false입니다.

~~~yaml
mud-optimizations:
  presentation-mob-tick: true
  retained-frames: true
  in-place-frame-prefix: true
~~~

이 설정은 플러그인이 체력·이동·전투를 전부 관리하는 MUD 외형 엔티티를 위한 것입니다. 수동 재배치는 일반 teleport를 사용하며 연속 경로 이동만 별도 서버 경로를 사용합니다. 패킷 옵션은 프로토콜 payload를 바꾸지 않고 버퍼 복사를 줄입니다. 클라이언트 화면 렌더링·원격 네트워크·다른 패킷 플러그인과의 조합 검증은 별도입니다.

Rust FFM/JNI 모듈은 제거되었습니다. 전투 계산과 엔티티 이동 배치는 Java로 실행하며 외부 MUD DLL을 로드하지 않습니다. 과거 native 성능 수치는 비교 기록으로만 남깁니다.

## 명령과 운영

0.6.0부터 `/mud`로 입장 메뉴, `/mud start` 또는 인수 없는 `/mud join`으로 빈 6×6 개인 전장 자동 배정, `/mud lobby`로 퇴장이 가능합니다. 한 플레이어는 한 세션만 가지며 사용 중인 전장은 중복 배정하지 않습니다. 패배·시간 초과·100라운드 클리어 즉시 해당 세션의 몹·청크 티켓을 정리하고 로비로 복귀합니다. 빈 전장은 새로운 초기 재화와 라운드로 재사용합니다.

`plugins/MCLuckDefense/lobby.yml`을 활성화하면 접속·리스폰·게임 종료 시 지정한 로비 스폰을 사용합니다. F키는 로비에서 입장 메뉴를, 게임 중에는 소환·판매 메뉴를 엽니다. 로비는 블록 변경·피해·허기·드롭·포탈을 막고 경계 밖/낙하 시 스폰으로 복귀합니다. 설정 기본값은 비활성이므로 기존 서버에 빈 로비를 자동 생성하지 않습니다. 비활성 상태에서는 게임 종료 시 기존 입장 위치로 복귀합니다.

사용자 제공 `starhill120.schem`의 가져오기와 검증은 [로비 설치 기록](docs/lobby.md)을 참고하세요. 스케메틱 원본 및 생성된 월드는 저장소에 포함하지 않습니다.

| 명령 | 권한 | 설명 |
|---|---|---|
| /mud list | moma.play | 전장 목록 |
| /mud join <이름> | moma.play | 개인 전장 참가, 100라운드 시작 |
| /mud leave | 없음 | 게임 종료 |
| /mud create <이름> | moma.admin | 6×6 전장 생성 |
| /mud spawn <종> [수] [boss] | moma.admin | 보상 없는 개발용 적 추가 |
| /mud coins <금액> | moma.admin | 개발용 재화 지급 |

명령은 /moma에서 /mud로 변경했고 기존 권한 노드 moma.play/moma.admin은 유지합니다. 플레이 권한은 기본 허용, 관리자 권한은 기본 OP입니다. 관리자 개입 명령을 사용한 판은 결과에 표시합니다.

전장은 moma_arenas 월드에 128블록 간격으로 생성되며 기존 블록을 덮어쓰지 않습니다. **이전 5×5 전장은 참가가 거절됩니다. /mud create 새이름으로 6×6 전장을 생성한 뒤 참가하세요.** 기존 지형·목록은 보존하며 자동 확장하지 않습니다. 이전 개발용 config.yml은 더 이상 읽지 않습니다. 정식 캠페인은 패키지에 포함된 campaign.properties를 사용합니다.

전장 목록은 plugins/MCLuckDefense/arenas.yml에 저장됩니다. 진행 중 라운드·유닛·재화는 메모리에만 있으며 퇴장·접속 종료·서버 종료 시 정리됩니다. 로비 활성화 시 종료 후 로비로 돌아가며 비활성화 시 이전 위치·게임 모드를 복구합니다. 재접속 이어하기와 크래시 복구는 지원하지 않습니다.

## 0.8.1 세션 배속·기본 비행·대형 몹 크기

- F GUI 오른쪽 위 시계 버튼으로 1 → 2 → 4 → 8 → 1배 전환. `/mud speed <1|2|4|8>`도 지원합니다. 기본값은 1배이며 새 게임은 1배로 시작합니다. 관전자는 대상 게임의 배속을 변경할 수 없습니다.
- 서버 TPS는 그대로 두고 각 세션의 게임 시간을 독립적으로 진행합니다. 준비 시간·웨이브·적 이동·공격 대기·감속이 동일한 비율로 빨라지고, 변경 시 공격 상태나 대기 시간을 초기화하지 않습니다. 화면의 남은 시간은 게임 시간입니다. 배속 변경은 재화·스펙·확률을 바꾸지 않으며 플레이어의 입력 속도는 가속하지 않습니다.
- 한 서버 틱 안의 모든 전투 판정과 처치 보상을 처리하되, 엔티티 위치·방향은 마지막 상태를 전송합니다. 포탑마다 마지막 실제 공격의 범위·연결선·소리만 한 번 표시합니다. 서로 다른 공격의 다중 타깃을 하나로 합치지 않습니다. 8배속은 전투 연산을 늘리므로 동시 고배속 세션이 많으면 부하가 증가합니다.
- 게임 참가자와 관전자는 입장 시 비행을 허용하고 켭니다. 로비 접속·귀환·리스폰 시 비행을 해제하며, 로비 비활성 서버는 퇴장·접속 종료 시 기존 게임 모드와 비행 상태를 복구합니다.
- 가스트·워든·철골렘·파괴수·호글린·북극곰·판다는 scale 1.0, 나머지 아군과 적은 2.0입니다. 이 변경은 모델 크기에만 적용하며 공격력·사거리·피해 범위는 동일합니다.
- 참가 시 1번 슬롯에 선택·이동 막대, 2번 슬롯에 판매 에메랄드를 지급합니다. 1번 도구를 들고 아군/빈 칸을 좌클릭해 선택·이동하고, 2번 도구를 들고 우클릭하면 선택한 포탑을 판매합니다. 전설 이상 판매 제한은 동일합니다. 도구는 이동·드롭할 수 없으며, 기존 두 슬롯의 아이템은 플레이어 데이터에 백업하여 퇴장·접속 종료·재접속 시 복구합니다.
- 소환·판매 GUI의 클릭 대기 시간을 5틱에서 1틱(정상 20 TPS에서 약 50ms)으로 줄였습니다. 같은 틱의 중복 이벤트와 이전 세션의 메뉴는 거절합니다.

## 0.8.2 GUI 사운드 피드백
