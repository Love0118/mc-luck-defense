# 1.0.0 — 시즌 1 시작과 프리시즌 순위표

기존 최고 라운드 기록을 프리시즌으로 보관하고 새 시즌 1 순위표를 시작한다. 전투·소환 밸런스는 0.20.0 확정 수치를 사용한다.

## 로비

스폰 앞 기존 위치에는 **시즌 1 최고 라운드**, 옆에는 **프리시즌 최고 라운드**를 표시한다. 각 표는 10명씩 보여주며 이전/다음 버튼을 좌클릭 또는 우클릭해 넘긴다. 페이지는 플레이어별·시즌별로 독립적이다. 프리시즌은 보관된 기록을 보여주고 새 플레이 결과는 시즌 1에만 반영한다.

## 데이터 이전

최초 적용 시 플러그인 데이터 폴더의 `round-records.properties`를 읽어 `leaderboards.db`로 이전한다.

- `round_records` 테이블의 `season=0`은 프리시즌, `season=1`은 시즌 1이다. 키는 시즌과 플레이어 UUID의 조합이다.
- 프리시즌에는 기존 UUID·이름·최고 라운드를 그대로 저장한다. 시즌 1은 기록 없이 시작한다.
- 테이블 생성, 전체 기록 가져오기, SQLite `user_version=1` 설정은 하나의 쓰기 트랜잭션으로 처리한다. 실패 시 모두 되돌리고 다음 적용에서 재시도할 수 있다.
- 완료 후에는 기존 파일을 다시 가져오거나 시즌 1을 지우지 않는다. 기존 파일도 수정하거나 삭제하지 않는다.
- 신규 설치는 두 시즌 모두 빈 상태로 초기화한다. 초기화 뒤 추가된 구형 파일은 자동으로 다시 가져오지 않는다.
- 시즌 1 저장도 트랜잭션으로 처리하며 이전 최고 라운드를 낮추지 않는다. 외부에서 수정한 더 최신 DB 형식은 덮어쓰지 않고 거절한다.

이전 대상은 순위표다. 업적 달성·특성 해금 등 다른 플레이어 데이터는 해당 저장소에 그대로 유지된다. 원본 파일이 잘못되었거나 DB 이전에 실패하면 새 런타임 활성화를 실패 처리하여 정상적인 업데이트 복구 경로로 돌아간다.

## 적용

버전은 **1.0.0**, 런타임 상태 형식은 **4**다. 시즌 경계를 넘는 업데이트이므로 진행 중인 게임이 있으면 적용을 거절한다. 세션이 모두 끝난 뒤 `/mud update`로 적용하면 순위표 이전과 생성이 자동 실행된다. `/mud reload check`만 실행하는 단계에서는 순위표 데이터를 변경하지 않는다.

배포는 `beta` 푸시와 기존 자동 빌드·릴리스 경로를 사용한다. 이번 작업에서는 라이브 서버의 DB·JAR를 직접 교체하거나 서버를 재시작하지 않는다.

## 검증 결과

전체 Java 테스트 **350개**, Python 결과 검증기 테스트 **3개**를 통과했다. 다음 순위표 검사는 실제 임시 SQLite와 Paper API 모의 객체를 사용했으며 라이브 서버에서는 실행하지 않았다.

실제 임시 SQLite DB로 기존 기록 보존, 새 시즌 독립 기록, 재실행 시 중복 이전 방지, 동시 초기화, 잘못된 원본의 트랜잭션 복구·재시도, 저장 실패 시 부분 쓰기 방지, 상위 DB 버전 거절을 검증했다. 로비 테스트는 두 시즌의 표식, 개인 가시성, 독립 페이지 이동, 새 기록 반영 범위, 엔티티 재생성, 종료 시 저장을 검증했다.
