# 1.0.7 — 밸런스 변경 강제 리로드

관리자에게 명시적인 `force` 옵션을 추가했다. 실행 중인 세션의 밸런스 지문이 달라도 새로운 게임 코드를 적용할 수 있다. 이전 빌드의 세션 스냅샷을 먼저 복원하고 전투 상태 지문을 확인한 후 기존 런타임을 교체한다. 검증이나 활성화가 실패하면 기존 런타임으로 복구한다.

| 명령 | 동작 |
|---|---|
| `/mud reload check force` | 준비된 JAR로 강제 리로드 가능성을 사전 검사 |
| `/mud reload force` | update 폴더의 JAR 또는 현재 런타임으로 강제 리로드 |
| `/mud update force` | 최신 beta 다운로드·무결성 검사 뒤 강제 리로드 |
| `/mud rollback force` | 직전 런타임으로 강제 복원 |

기존 `check`, `reload`, `update`, `rollback` 명령은 기본 보호 규칙을 그대로 사용한다. `force`는 **밸런스 차이만** 허용한다. 플러그인 로더·의존성 설정 차이, 활성 세션의 저장 형식 차이, 세션 복원 지문 불일치, BGM 작업 중 리로드 불가 상태는 계속 거절한다. 세션에 저장된 라운드·골드·기물 능력치·공격 대기시간은 그대로 복원하므로 이전 기물의 능력치가 소급 변경되지는 않는다. 새로 생성되는 세션은 새 빌드의 규칙으로 시작한다.

명령 처리기가 영구 로더에 있으므로 이 기능을 처음 설치할 때는 Paper 서버를 한 번 정상 재시작해야 한다. 이후 로더가 같은 후속 빌드에서는 강제 리로드에 재시작이 필요하지 않다. 1.0.5에서 적용할 때는 1.0.6의 BGM 반복 다운로드 차단도 함께 포함된다. 런타임 상태 형식은 1.0.6과 동일한 **5**다.

## 검증

서로 다른 밸런스의 가상 JAR에서 기본 리로드·롤백 거절, 강제 검사·리로드·롤백 시 세션 상태 유지, 다운로드 업데이트의 force 전달, 로더·저장 형식 차이와 복원 오류의 거절을 테스트했다.

로컬 `mvn clean verify`에서 **357개 Java 테스트**, 결과 검증기 Python 테스트 **3개**가 통과했다.
