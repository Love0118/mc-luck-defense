# BGM / Dropbox 직접 배포

리소스팩 전용 참고 브랜치: https://github.com/Love0118/spear-vs-zombie/tree/resource-pack-only

해당 브랜치의 공개 OAuth 애플리케이션 키/시크릿과 동일한 값을 사용합니다. rclone 실행 파일이나 rclone 동기화 서비스는 사용하지 않습니다. 참고 브랜치의 refresh-token 설정은 비어 있으며 Dropbox 계정에 대한 로그인 권한은 포함되어 있지 않습니다.

## 최초 연결

1. 업데이트 후 서버를 재시작합니다.
2. 게임 내 관리자가 /mud bgm auth를 실행합니다.
3. 표시되는 Dropbox 연결 링크를 열어 사용할 계정을 승인합니다.
4. 발급받은 인증 코드를 게임 채팅에 입력합니다. 대기 중 입력은 일반 채팅 전달 전에 취소되어 다른 사람에게 전송되지 않습니다. 인증 코드를 명령어 인자로 넣지 않습니다.
5. 연결이 완료되면 기본 BGM 리소스팩을 자동 배포합니다. 연결 실패 시 인증을 다시 시작할 수 있습니다.

계정 refresh token은 서버 plugins/MCLuckDefense/bgm.yml에 저장됩니다. 이 파일을 공개하거나 Git에 올리지 마세요. 코드 입력 대기는 10분, YouTube 입력 대기는 2분이며 '취소'로 종료할 수 있습니다. 한 번 승인한 계정은 재시작 후에도 사용합니다.

## 조작

- 게임 주인: 7번 슬롯 주크박스 우클릭 → 2줄(18칸) BGM 관리 GUI.
- 본인이 등록한 곡은 0·1·2번 GUI 칸에 표시됩니다. 기본 BGM은 별도 버튼입니다.
- 하단 중앙(13번 칸): 노래 업로드. 하단 최우측(17번 칸): 업로드된 곡 모두 보기. 전체 목록은 페이지 이동을 지원합니다.
- 업로드 버튼 → 채팅에 YouTube 영상 URL → 서버 다운로드 → Ogg Vorbis 변환 → 곡별 ZIP 생성 → Dropbox API 업로드 → dl=1 링크 생성 → 배포 파일 SHA-1 검증 → DB 저장.
- 한 사람당 등록곡은 최대 3곡입니다. 곡 선택은 자기 세션 주인만 가능합니다. 전체 목록에서는 다른 사람이 업로드한 곡도 선택할 수 있습니다.
- 관전자: 7번 슬롯 주크박스로 개인 BGM ON/OFF만 조정합니다. 현재 게임 모델의 다른 청취자는 관전자이며 별도 멀티플레이 참가자 역할은 없습니다.
- 주인도 관리 GUI에서 자기 BGM을 끌 수 있습니다. 다른 사람의 청취 설정에는 영향을 주지 않습니다. 개인 ON/OFF는 재접속 후에도 유지됩니다.
- 공격 사운드 조절은 기존 8번 슬롯이며 BGM과 독립적입니다.

## 재생과 복구

곡을 선택한 세션의 청취자에게 해당 리소스팩을 링크로 전송합니다. 클라이언트가 적용 완료를 알린 뒤 MUSIC 채널로 재생합니다. 리소스팩을 거부하거나 다운로드/적용에 실패하면 안내하고 재생하지 않습니다. 클라이언트의 서버 리소스팩 허용 설정은 서버 플러그인이 강제로 우회하지 않습니다. 곡은 길이에 따라 반복되며 게임 배속과 무관합니다. 관전 시작/ON 시 곡의 시작부터 듣습니다. 퇴장·관전 대상 변경·곡 변경 시 이전 음악과 이 플러그인이 추가한 팩을 정리합니다.

SQLite DB plugins/MCLuckDefense/bgm.db에 업로더 UUID/이름, 제목, 원본 YouTube URL, 배포 링크, SHA-1, 길이를 저장합니다. DB는 단일 작업 스레드가 직렬로 접근합니다. 업로드·변환·네트워크·복구는 서버 틱 스레드에서 수행하지 않습니다.

시작 시 및 기본 30분 간격으로 배포 파일을 다운로드해 SHA-1을 검증합니다. 손상·삭제된 링크는 저장한 YouTube URL로 재다운로드/변환/배포한 후 DB를 갱신합니다. 기본 곡은 JAR에 포함한 Vorbis 원본으로 복구합니다. YouTube 영상 자체가 삭제·비공개·접근 제한 상태이면 복구할 수 없으며 다음 검사에서 재시도합니다. 실패한 링크가 복구되면 해당 세션에 새 팩을 요청합니다.

다운로드/변환 임시 파일은 플러그인의 bgm-work 하위에만 생성하고 완료·실패 시 제거합니다. 재시작 시 남은 작업 디렉터리도 정리합니다. 사용자 Downloads의 bgm1.ogg는 삭제하지 않습니다. Minecraft 클라이언트가 관리하는 resource-pack 캐시는 서버에서 삭제하지 않습니다.

## 외부 실행 도구

플러그인이 직접 ProcessBuilder로 yt-dlp와 FFmpeg를 실행합니다. 별도 백그라운드 프로그램이나 작업 스케줄러는 필요하지 않습니다. 이번 서버에는 다음을 준비했습니다.

- yt-dlp 2026.08.19: plugins/MCLuckDefense/tools/yt-dlp.exe
- SHA-256: 66674953fe251b89f4d08c5f0e35e0728679bd67ab3d7d05c0562af101dd3e7a (공식 GitHub release digest 확인)
- FFmpeg: plugins/MCLuckDefense/tools/ffmpeg.exe (기존 로컬 실행 파일 복사)
- JavaScript runtime: 설치된 Node.js. 도구 경로는 bgm.yml에 절대경로로 설정했습니다.

일반 영상만 허용하고 영상당 최대 10분, 다운로드 최대 25MB입니다. 프로세스 시간 제한과 32개 대기열을 사용하며 한 번에 하나의 업로드/복구를 처리합니다. 실행 인수는 셸 문자열로 조립하지 않습니다. YouTube 접근 방식 변경 시 yt-dlp 업데이트가 필요할 수 있습니다.

## 검증과 적용 상태

- Java/native 전체 테스트 193개 통과.
- 실제 Paper 26.3 서버의 3클라이언트 검증에서 SQLite 초기화, 18칸 GUI 및 버튼 위치, 주인·관전자 BGM 도구, 기존 게임·관전·개인 음량 검사 통과.
- YouTube 공개 영상 jNQXAC9IVRw로 실제 다운로드 → Vorbis 변환 → ZIP 생성 → 임시 파일 삭제 성공.
- DB 재시작·3곡 제한·복구 메타데이터 갱신, Dropbox HTTP 흐름과 SHA-1 검증은 테스트로 확인했습니다.
- Dropbox 계정 인증/실제 업로드는 계정 토큰 부재로 미실행입니다. 실제 Minecraft 클라이언트의 리소스팩 렌더링/청취도 별도 확인이 필요합니다.
- 제공된 bgm1.ogg는 Opus 형식이어서 Vorbis로 변환해 기본 곡으로 포함했습니다. 원본 약 110.82초.
- 팩 메타데이터는 1.21.8 리소스 형식 64부터 실제 26.3 형식 97.1까지 선언합니다. 오디오 전용이며 ViaVersion으로 전달되는 동일한 ZIP을 사용합니다.

운영 서버는 재시작하지 않습니다. 업데이트 JAR는 기존 설치 파일과 동일한 이름으로 plugins/update에 준비합니다. 내부 플러그인 버전은 0.10.0입니다.
