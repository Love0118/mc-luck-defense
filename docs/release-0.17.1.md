# 0.17.1 — BGM 연속 재생과 기존 음원 팩 갱신

곡 시작부터 듣는 세션 소유자와 관전자는 **전체 OGG를 한 번만 재생**한다. 같은 곡 안에서는 2초 경계를 지나거나 서버 틱이 잠시 늦어져도 StopSound·PlaySound를 재전송하지 않는다. 반복 재생이나 메들리의 다음 곡으로 넘어갈 때만 새 전체 음원을 재생한다. 음소거·세션 종료·곡 변경에는 기존처럼 즉시 멈춘다.

중간 입장하거나 음소거를 해제한 사람은 현재 곡의 재생 위치에 맞는 기존 2초 클립으로 합류한다. 이 사람만 해당 곡의 남은 구간에서 클립 전환을 사용하며, 다음 곡 시작부터 전체 음원 재생으로 전환한다. 따라서 **중간 합류자의 현재 곡까지 완전한 무음 간격 없는 재생을 보장하는 변경은 아니다.** 기존 세션 이용자의 음악은 관전자 합류 때문에 다시 시작하지 않는다.

## 기존 팩 자동 갱신

- 음원 팩 버전을 2 → 3으로 올렸다. 3에는 전체 음원과 중간 합류용 클립이 함께 들어 있다.
- 이전 2초 분할 전용 팩은 URL이 정상이어도 새 형식으로 재생성한다. 기본곡은 내장 원본, 업로드곡은 저장된 YouTube 원본 주소에서 다시 가져온다.
- 새 팩이 생성되면 SQLite의 버전·URL·SHA-1을 갱신한다. 새 해시로 팩 UUID가 바뀌므로, 접속 중인 클라이언트도 이전 팩을 내리고 새 팩을 받는다. 이후 접속자 역시 새 팩을 요청한다.
- 변환 대기 중에는 한 번 안내하고, 팩 적용이 끝난 뒤 재생한다. 업로드곡·재생 목록을 삭제하거나 사용자에게 전부 재등록시키지 않는다.
- 변환은 기존 단일 백그라운드 작업자가 순서대로 수행한다. 곡이 많으면 시간이 걸리며, YouTube 원본 삭제·접근 제한·Dropbox 실패가 있으면 해당 곡은 보류하고 다음 점검에서 재시도한다.
- 이미 새 형식이며 정상인 팩은 다시 변환하지 않는다.

Semion에서 확인한 이전 형식 곡은 62개다. 설치된 yt-dlp 2024.04.09는 현재 플러그인의 옵션을 지원하지 않아, 서버 전용 가상환경에 2026.08.19를 설치하고 bgm.yml의 도구 경로를 갱신했다. 인증 정보는 유지했다. 새 설정과 팩 변환은 새 런타임 적용 시 시작한다.

## 검증

Maven 테스트 272개 통과. 전체 음원 및 동기화 클립의 팩 구성, 2초 경계·틱 지연에서 기존 청취자에게 재생/중단 패킷을 보내지 않는 동작, 늦은 관전자만 위치 맞춤을 사용하는 동작, 다음 곡의 연속 재생 전환, 이전 팩의 강제 재생성 및 새 해시 다운로드 요청을 검사했다. 실제 사람이 게임 음성을 청취한 검증은 아니다.

0.17.0과 영구 로더 및 전투 밸런스를 유지한다. `/mud update`로 받아 기존 안전 리로드 검사를 거쳐 적용할 수 있다. BGM 업로드나 변환 작업이 진행 중이면 완료 후 다시 실행해야 한다.

[beta CI](https://github.com/Love0118/mc-luck-defense/actions/runs/35685818048)의 테스트·시뮬레이션·배포가 성공했다. 공개된 JAR를 실제 업데이터 코드로 내려받아 검증했고, 이전에 설치한 CI 0.17.0과 로더·밸런스·스키마 지문 일치를 확인했다. SHA-256: `ecec7ffc6a9d40235003ebf22d9ff8ed09deef0c8f941f928835d6ada0a45a02`.

로컬과 semion의 update 폴더에 동일한 JAR를 준비했다. 이번 작업에서 서버 재시작이나 라이브 리로드는 실행하지 않았다. 62개 곡의 실제 일괄 변환은 `/mud update` 적용 이후 백그라운드에서 진행된다.
