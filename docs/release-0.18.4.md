# 0.18.4 — 분할 BGM 구간 누락 완화

분할곡을 듣는 중 서버 틱이 구간 시작보다 150ms 넘게 늦어지면 현재 코드는 이전 소리를 중지하고 해당 2초 구간을 통째로 건너뛰었다. 다음 틱도 같은 조건에 걸려 다음 경계까지 무음이 이어질 수 있었다. 이미 늦게 시작한 구간도 다음 전역 경계에서 강제로 중지되어 뒷부분이 잘렸다.

이번 변경은 이미 재생 중인 분할곡에 다음을 적용한다.

- 구간 전송 시점부터 실제 구간 길이를 기다린 뒤 다음 구간을 보낸다. 정상 연결에서 StopSound를 보내지 않는다.
- 150ms를 넘게 늦어도 현재 구간을 보낸다. 여러 구간을 지나칠 정도의 긴 정지는 현재 타임라인 구간부터 재개하고 과거 구간을 몰아서 재생하지 않는다.
- 첫 합류는 기존처럼 가까운 2초 경계에 맞추고 다음 곡·반복부터 전체곡으로 전환한다. 곡 변경·음소거·퇴장·리소스팩 재적용 시 정지는 유지한다.
- 구간 번호와 다음 전송 시각을 세션 리로드 상태에 보존한다. 구형 진행 상태는 다음 타임라인 경계부터 이어간다.

새 팩이나 음원 재다운로드는 필요 없다. 전체곡 재생 중에는 2초 간격 명령을 보내지 않는다.

## 클라이언트 예약 재생의 한계

지원 중인 1.21.8의 [위치 사운드 패킷](https://maven.fabricmc.net/docs/yarn-1.21.8%2Bbuild.1/net/minecraft/network/packet/s2c/play/PlaySoundS2CPacket.html)과 [엔티티 사운드 패킷](https://maven.fabricmc.net/docs/yarn-1.21.8%2Bbuild.1/net/minecraft/network/packet/s2c/play/PlaySoundFromEntityS2CPacket.html)에는 시작 시각·지연·재생 목록 필드가 없다. 클라이언트 내부 [SoundManager.play(sound, delay)](https://maven.fabricmc.net/docs/yarn-1.21.8%2Bbuild.1/net/minecraft/client/sound/SoundManager.html)는 존재하지만 서버가 이 예약 기능을 지정하는 일반 사운드 패킷은 없다. 원하는 예약 목록을 처리하려면 클라이언트 모드 등의 수신 구현이 필요하다.

따라서 이번 수정은 서버가 만들어 내던 불필요한 정지와 구간 누락을 줄이는 조치다. 네트워크 지터·클라이언트 디코딩·리소스 재로딩 지연을 없애거나 무간격 재생을 보장하지 않는다. 완벽한 동기화보다 해당 구간을 끝까지 듣는 쪽을 우선하여 중도 청취자는 전역 타임라인보다 늦어질 수 있고 다음 곡에서 다시 맞춘다.

다른 리소스팩의 적용 완료도 클라이언트 사운드를 다시 로딩하므로 재생을 끊을 수 있다. 기존 성공 이벤트 처리에서 재동기화하는 이유이며, 이번 변경만으로 여러 팩 적용 중 발생하는 끊김까지 해결했다고 주장하지 않는다. 재생 목록을 미리 모두 적용하거나 팩을 묶는 개선은 별도 범위다.

## 검증

400ms 늦은 구간 호출에서 누락 없이 한 번 재생, 다음 경계에서 조기 중지하지 않음, 구간 종료 전후 호출, 중복 틱, 세션 직렬화·복원, 마지막 짧은 구간, 다음 곡의 전체 재생 전환을 회귀 테스트한다. 기존 소유자 전체곡·중도 관전·개인 음소거·팩 실패/재적용·메들리 검사도 함께 수행한다. 실제 클라이언트 청취나 네트워크 패킷 수신 시각을 측정한 결과는 아니다.
