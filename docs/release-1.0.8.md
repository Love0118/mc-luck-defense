# 1.0.8 — 시즌 1 최고 라운드에 따른 BGM 업로드 한도

플레이어별 BGM 등록 한도를 `20 + 5 × floor(시즌 1 최고 라운드 / 100)`곡으로 정한다. 0~99라운드 20곡, 100~199라운드 25곡, 200~299라운드 30곡이다. 프리시즌과 다른 누적 업적 라운드는 한도에 반영하지 않는다. 접속 시 시즌 1 순위 기록을 복원하고, 현재 판의 새 기록은 즉시 반영한다.

GUI의 업로드 아이콘에 현재 등록 수/한도와 해금 규칙을 표시한다. 업로드 링크를 입력할 때의 한도를 작업에 전달한다. 작업 스레드에서 전환·다운로드 전에 한도를 다시 확인하며, DB 저장에서도 같은 한도를 적용한다. 기존 곡의 복구와 제목·배포 링크 갱신은 한도를 이미 채웠어도 허용한다. 기존 업로드 곡과 개인 재생 목록은 변경하지 않는다.

`bgm.yml`의 `limits.uploads-per-player`는 기본 슬롯 수로 사용하되 **최소 20**이다. 예전 파일에 3이나 12가 적혀 있어도 적용되는 기본 슬롯은 20이다. 20보다 큰 값을 설정한 경우 해당 수를 기본으로 사용하고 시즌 1 기록에 따른 슬롯을 더한다. 설정 파일 내용은 자동으로 다시 쓰지 않는다. `playlist-tracks`는 독립적인 재생 목록 한도다.

1.0.7과 영구 로더·런타임 상태 형식 **5**가 같다. 서버에서 게임 관리 명령에 접근할 수 있으면 BGM 작업이 끝난 뒤 `/mud update force`로 세션 유지 적용이 가능하다. 이번 오라클 서버 적용은 운영 접근 방식에 따라 별도로 검증한다.

## 검증

99/100/199/200/2000라운드 경계의 한도, DB에서 등록 한도의 재검사와 복구 허용, 예전 낮은 설정의 최소 20곡 적용, BGM GUI의 표시를 검사한다.

`mvn clean verify`에서 **358개 Java 테스트**, 결과 검증기 Python 테스트 **3개**가 통과했다.
