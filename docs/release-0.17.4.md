# 0.17.4 — 다른 곡의 준비 상태가 현재 곡 재생을 막는 문제 수정

0.17.3은 선택한 곡을 클라이언트가 적용했어도 소유자의 전체 보관함과 재생 목록이 모두 준비될 때까지 재생을 막았다. 기존 팩 변환 중이거나 사용하지 않는 곡 하나가 다운로드에 실패하면 기본곡도 들리지 않을 수 있었다.

이제 소유자가 첫 재생 곡의 팩을 적용하면 세션 음악을 시작한다. 각 청취자는 현재 곡의 팩 적용 여부로 재생을 결정한다. 보관함 전체 사전 다운로드는 계속하지만, 다른 곡의 준비·실패 상태 때문에 현재 곡을 중단하지 않는다. 현재 곡 자체가 적용되지 않았다면 소리를 보내지 않으며 중도 합류의 분할 재생과 다음 곡부터 전체곡 전환은 유지한다.

2026-09-22 Semion에서는 0.17.3 적용 후 쿠키 인증을 사용한 변환이 진행 중이었다. 점검 중 전체 62곡의 최신 팩 수가 19개에서 23개로 증가했고, 그 기간 신규 변환 실패 로그는 없었다. 이는 서버 팩 생성 상태이며 특정 사용자의 클라이언트 다운로드 완료 수는 아니다.

회귀 검사: 기본곡 하나만 적용하고 다른 보관함 곡이 구형 팩이거나 다운로드 실패 상태여도 소유자·관전자 재생이 시작된다. 메들리의 다음 곡이 실패해도 현재 곡은 유지하고, 다음 곡 재생 시점에는 그 팩이 적용되어야 한다. 단순 `DOWNLOADED` 알림을 팩 적용 완료로 취급하지 않는다.

클라이언트가 새 팩을 실제로 적용하면 사운드 재로딩을 고려하여 현재 타임라인에 한 번 다시 합류한다. 곡 중간에는 분할곡으로 복귀하며 중복 적용 완료 알림으로 재생을 반복 초기화하지 않는다. 테스트에서는 4초 시점에 다른 팩 적용 후 현재 곡의 해당 분할곡으로 복귀하는지 확인한다.

적용은 `/mud update`를 사용한다. 진행 중인 BGM 변환 작업이 있으면 기존 안전 리로드 검사가 업데이트를 보류하므로 작업 완료 후 적용해야 한다. 서버 재시작이나 라이브 곡 목록 변경은 수행하지 않았다.
