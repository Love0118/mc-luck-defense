# 0.19.0 — 10,000라운드·대기열·상위 소환 검증

동일 시드 28,000,000~28,000,999를 구성별로 실행했다. **무특성 1,000판, 최고 성장 특성 1,000판, 최고 전투 특성 1,000판**, 총 3,000판이다. 10,000라운드를 상한으로 실제 전투·처치 보상·소환·합성·판매·배치를 처리했다. 목표 라운드에 강제로 도달시키거나 적 체력을 낮추지 않았다.

최고 전투 구성에서 2판, 최고 성장 구성에서 1판이 10,000라운드에 도달했다. 무특성 구성에서는 관측하지 못했다. 희귀 성공 수가 작아 0.1~0.2%를 확정적인 플레이어 도달률로 간주하지 않는다. 0/1,000도 불가능함을 증명하지 않는다.

## 설정과 특성

| 구성 | 장착 특성 | 패시브 |
|---|---|---|
| none | 없음 | 없음 |
| top_growth | 기적의 담금질 +30%p, 전우의 재회 +25%p, 전장의 투자 +8% | 첫 두 구매 에픽 이하 +1, 초반 서사·전설·에픽·신화 보정 모두 |
| top_combat | 수비 교본 피해 +21%, 신속한 지휘 공속 +8%, 기적의 담금질 +30%p | 위와 동일 |

각 구성은 해당 업적을 이미 해금한 계정을 가정하며 최대 3개 장착 제한을 따른다. 같은 계열의 여러 티어를 중첩하지 않는다. 두 최고 티어 조합은 대표 사례이며 가능한 모든 조합의 최적해를 탐색한 것은 아니다.

자동 플레이어는 현재 상태만 보고 게임 틱당 최대 4개의 구매/판매 행동을 한다. 돈 또는 총 보유 공간이 부족하면 대기열의 판매 가능한 약한 기물을 판매한다. 진 태초·미라클을 자동으로 팔지 않는다. 구매 후 실제 AutoPlacement를 사용하여 높은 등급의 기물을 우선 출전시킨다. 전장 36칸+대기열 48칸이며 합성은 ON이다.

이 정책은 과거 36칸 전용 시뮬레이터의 배치·판매 정책과 다르다. 아래 수치는 기존 10,000판 생존 곡선과 직접 동등 비교할 수 없으며, 실제 사용자의 자동판매 등급 선택이나 수동 교대 전략까지 나타내지 않는다. 후속 밸런스 조정은 이 차이를 고려해야 한다.

## 도달률

각 구성 1,000판이므로 0.1%는 1판이다. 라운드 진입 기준이다.

| 구성 | 30R | 60R | 100R | 200R | 300R | 500R | 1,000R | 2,500R | 10,000R |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 무특성 | 89.6% | 68.6% | 68.6% | 15.5% | 0.1% | 0% | 0% | 0% | 0% |
| 최고 성장 | 99.5% | 95.6% | 95.6% | 32.9% | 2.7% | 0.3% | 0.1% | 0.1% | 0.1% |
| 최고 전투 | 100% | 99.8% | 99.8% | 34.2% | 1.6% | 0.3% | 0.2% | 0.2% | 0.2% |

무특성 최고 관측은 373라운드였다. 최고 티어 특성을 단 계정도 대부분 1,000라운드 이전에 탈락했다. 살아남은 극소수만으로 2,000 이후 난이도 전체가 균형 잡혔다고 결론내리지 않는다. 이번 작업은 기본 체력 곡선에 새 도달률 목표를 강제로 맞추지 않았다.

전체 중간 체크포인트·구매 횟수·판매 횟수·획득 골드는 [원본 요약](runs/summary.csv)과 각 구성의 gzip JSONL에 보관했다. 성공 시드: 성장 `28000013`, 전투 `28000258`, `28000687`.

## 500배속과 결과 일치

시뮬레이터는 가상 20Hz 프레임마다 **500게임 틱**을 순서대로 처리한다. 500틱을 하나의 거대한 전투 틱으로 바꾸거나 중간 공격·보상·소환을 생략하지 않는다. 오프라인 결과 생성은 인위적인 실시간 대기 없이 실행하며 `effective_speed`는 전체 판의 누적 게임 시간을 실제 경과 시간으로 나눈 처리량이다. 병렬 실행을 합친 값이므로 개별 Minecraft 서버의 TPS나 개별 게임이 항상 정확히 현실 500배 속도로 흘렀다는 의미가 아니다.

성공 시드 3개 각각을 **1 / 32 / 500틱 단위로 다시 실행**했다. 10,000라운드까지 최종 라운드·처리 틱·구매·판매·최고 등급·중간 보상 스냅샷의 JSON이 동일했다. [동일성 기록](equivalence/equivalence.csv). 구간별 파일도 같은 폴더에 보관했다.

별도 GameService 회귀 테스트는 실제 플러그인의 서버 틱 처리 경로에서 1배/32배의 전투 결과와 1,000·2,500라운드 경계의 구매·판매가·강화·배치·소환 단계 전환이 같음을 검사했다. 서버가 늦어도 논리 결과는 보존되지만 실제 처리량이 32배속을 따라가는지는 별도 네이티브 부하 측정이 필요하다.

## 기능 검증

- 전장에 36기, 대기열에 48기를 넣은 상태에서 85번째 새 기물 구매는 비용 차감 없이 거절한다. 같은 기물 합성은 공간을 추가로 차지하지 않으면 가능하다.
- 대기 기물은 전투 순회에 없고 공격 대기시간이 진행되어 추가 공격을 실행하지 않는다. 꺼낼 때 기존 공격 대기시간을 초기화하지 않는다.
- 높은 등급 자동 선발, 빈 칸 배치, 점유 칸과 교대, 대기열 판매, 실제 엔티티 생성 실패 복구를 검사했다.
- 진 태초·미라클의 자동판매 거절과 수동판매 1회 지급, 소환 단계별 재료 판매가 합산을 검사했다.
- 1,000/2,500 정확한 해금 경계, 모든 확률 구간의 양끝, 0.001% 결과의 존재, 진 태초 +20 → 미라클 승급을 검사했다.
- 1~10,000라운드의 모든 웨이브를 생성하여 유한한 적 체력·보상·유효한 출현 시각을 검사했다.
- 48칸 대기열 GUI의 두 페이지·소유권·오래된 메뉴·중복/Shift/하단 클릭·드래그 차단과 미라클 그라데이션을 검사했다.
- 대기열·판매가·선택·강화·배속의 저장 복원과 실제 공개된 0.18.4 상태 읽기를 검사했다.
- 고배속 도중 공격했던 기물이 보관·판매·이동된 경우 오래된 이펙트가 잘못된 위치에서 나오거나 예외를 내지 않도록 검사했다.
