# 0.11.0 세션 BGM 동기화·재생 목록

## 조작과 다운로드

- 재생 채널은 RECORDS입니다. Minecraft 소리 설정의 주크박스/음표 블록 슬라이더로 자연스럽게 음량을 조정합니다. 개인 BGM ON/OFF도 유지합니다.
- 주인의 7번 슬롯 관리 도구 → 18칸 GUI. 0~2번 칸은 최대 3곡의 재생 목록입니다.
- 곡 좌클릭: 단일곡 선택·반복. 우클릭: 재생 목록에서 제거.
- 5번 칸: 단일곡/메들리 전환. 메들리는 목록 순서대로 반복합니다. 목록이 비어 있으면 기본 BGM을 사용합니다.
- 하단 중앙 업로드와 하단 우측 전체 곡 목록은 유지합니다. 전체 목록에서 다른 사람이 올린 곡을 클릭해 추가할 수 있습니다. 등록곡 소유권과 1인당 업로드 3곡 제한은 바뀌지 않습니다. 선택 목록은 별도로 최대 3곡이며 DB에 저장됩니다.
- 참가·관전 시 방장 등록곡 최대 3개와 선택한 타인 곡의 팩을 모두 요청합니다. BGM을 OFF로 해도 사전 다운로드하며, 이미 적용한 팩은 OFF/ON 시 다시 요청하지 않습니다. 세션 퇴장 때 이 플러그인이 보낸 팩만 제거합니다.

## 실제 시간 동기화와 바닐라 한계

Minecraft 26.3의 ClientboundSoundPacket 및 ClientboundSoundEntityPacket에는 오디오 seek/재생 시작 초 필드가 없습니다. 동일한 완곡 파일을 보내는 것만으로 중간 위치부터 재생할 수 없습니다.

곡을 2초 단위 Ogg Vorbis 조각으로 리소스팩에 포함하고, 세션 공통 System.nanoTime 기반 시계로 재생 조각을 선택합니다. 방장의 현재 재생 대상 팩이 준비되면 시계를 시작하며 게임 1/2/4/8배속과 독립적으로 흐릅니다. 중간 입장자는 다운로드·적용 완료 뒤 다음 조각 경계에 합류합니다. OFF에서 ON으로 돌아올 때도 현재 경계에 합류하고 처음부터 재생하지 않습니다. 메들리의 마지막 짧은 조각도 실제 곡 길이를 사용합니다.

이 방식은 조각 단위 동기화입니다. 정상 20 TPS에서 적용 완료 후 합류까지 최대 약 2초가 걸리며, 네트워크·클라이언트 지연은 별도입니다. 조각 경계의 틈/클릭과 클라이언트 음량 0→복원 동작은 실제 청취 환경에 따라 달라질 수 있습니다. 샘플 단위 동기화나 무손실 연속 재생을 보장하지 않습니다. 서버가 크게 지연되면 이미 지난 조각을 재생하지 않고 다음 경계까지 기다립니다.

DB의 기존 완곡 팩은 pack_version=0으로 마이그레이션하고 현재 분할 팩 버전 2와 구분합니다. Dropbox 연결 후 원본 YouTube/내장 기본곡으로 자동 재생성·배포합니다. 기존 팩이 분할 팩으로 재생성되기 전에는 동기화 재생에 사용하지 않습니다.

## 검증

- Java/native clean verify: 198 tests, 실패·오류·스킵 0.
- 실제 Paper 26.3의 3클라이언트 통합 검사 통과.
- 기본 110.82초 곡의 FFmpeg 분할 실행: 56개 Ogg 조각, ZIP 1,522,467바이트, 임시 파일 정리 확인.
- 공통 시계, 늦은 입장, 메들리 경계, 단일곡 루프, 패킷 RECORD 채널, 개인 mute, 전체 사전 다운로드, DB 마이그레이션 및 재접속용 목록 저장을 테스트했습니다.
- Dropbox 계정 refresh token이 아직 없으므로 실제 재배포 및 Minecraft 오디오 청취 검증은 미실행입니다. /mud bgm auth로 한 번 계정을 연결해야 합니다.
