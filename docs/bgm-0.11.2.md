# 0.11.2 팩 적용 완료 후 동기화

각 플레이어에게 보낸 팩 UUID별 PlayerResourcePackStatusEvent를 확인합니다. ACCEPTED(수락), DOWNLOADED(다운로드 완료)는 재생 허용 상태가 아닙니다. SUCCESSFULLY_LOADED(리소스 적용 완료)를 받은 팩만 준비된 것으로 판정합니다.

방장 등록곡·선택된 타인 곡·필요한 기본곡을 포함한 모든 사전 로딩 대상이 준비되어야 합니다. 아직 배포 준비 중인 곡도 준비 판정에서 제외해 통과시키지 않습니다. 방장의 전체 팩이 준비되면 세션 실시간 시계를 시작하고, 늦게 들어온 청취자는 자신의 전체 팩이 적용된 뒤 다음 2초 구간 경계에서 합류합니다.

거절·실패·무효 URL·적용 실패·팩 해제·시간 초과 시 재생하지 않습니다. BGM OFF→ON으로 실패한 팩만 다시 요청할 수 있으며 이미 성공한 팩은 유지합니다. 알 수 없는 UUID 응답은 무시합니다. 적용이 끝나면 플레이어에게 완료 안내를 표시합니다.

이는 Minecraft 클라이언트가 보낸 상태 응답에 근거한 확인입니다. 서버가 사용자 PC의 파일을 직접 검사하거나 변조된 클라이언트 응답의 진실성을 검증하는 기능은 아닙니다. 배포 시 SHA-1 검증과 클라이언트에 해시 전달은 유지합니다.

전체 201개 Java/native 테스트 통과. 다운로드만 완료한 상태, 일부 팩만 성공한 상태, 실패 후 지연 성공 응답, 실패 팩 재요청, 모든 팩 적용 후 재생을 검사했습니다. 실제 클라이언트의 원격 Dropbox 다운로드/청취는 계정 인증 후 별도 확인이 필요합니다.
