# Starhill 로비 및 개인 세션

MC Luck Defense 0.6.0은 **로비 대기 → 개인 전장 배정 → 탈락/클리어 → 로비 복귀**를 구현합니다. 게임 시작은 플레이어별이며 다른 세션의 라운드·재화·몹에 영향을 주지 않습니다.

## 설치된 로비

- 원본: 사용자가 지정한 `starhill120.schem`, SHA-256 `0bce285bdbf0348bbe7739deee85a5d801f3f8672ec51639589e703d725fbc3d`
- Sponge v2, 원본 DataVersion 3578, 선택 크기 512×355×512
- 실제 블록: 10,466,021개, 블록 엔티티 320개, 일반 엔티티 없음
- 별도 월드 `mud_lobby`, 원본 최소 좌표를 (-256, 0, -256)에 배치. 선택 상단은 공기이며 실제 최고 블록 y=232.
- 중앙 광장 스폰: (-5.5, 54, 4.5), yaw=180, pitch=0. 기존 바닥과 머리 공간을 확인하며 새 광장을 덮어쓰지 않습니다.
- Paper 26.3 저장 경로: `world/dimensions/minecraft/mud_lobby/region`

## 다시 가져오기

서버를 종료한 상태에서만 작업합니다. 원본과 월드는 공개 저장소에 배포하지 않습니다.

```powershell
python -m pip install numpy nbtlib
python scripts/import_lobby_schematic.py <starhill120.schem> <새로운-출력-폴더>
```

변환기는 기존 출력 폴더를 거절하고 1,024개 청크의 Anvil region을 새로 만듭니다. 블록 상태와 블록 엔티티 NBT, 원본 DataVersion을 유지하여 Minecraft가 버전에 맞게 변환합니다. 생성된 `region`을 비어 있는 전용 차원 폴더로 복사하고, `plugins/MCLuckDefense/lobby.yml`의 `enabled: true`를 설정합니다. 다른 월드 region에 덮어쓰지 마세요. 모서리와 16블록 경계를 맞추기 위해 원본 WorldEdit 선택 오프셋 대신 문서화된 새 원점을 사용합니다.

`lobby.yml`이 비활성이면 기존 입장 위치 복귀 방식으로 실행합니다. 활성화했는데 스폰 바닥/머리 공간이 잘못되어 있으면 로딩을 실패시켜 공중 로비로 보내지 않습니다. 로비 월드는 재시작 시 다시 붙여넣지 않습니다.

## 검증

2026-09-20, 실제 Paper 26.3-mud의 별도 localhost 서버에서 확인했습니다.

- 원본의 480개 블록 상태 각각을 실제 월드에서 조회해 일치 확인. 옛 grass는 업그레이드된 short_grass로 확인.
- 프로토콜 클라이언트 2개가 지정 로비 스폰으로 접속.
- 서로 다른 개인 전장 배정 및 실제 아군 소환·웨이브 적 생성.
- 적 한도 패배 시 엔티티 제거·세션 해제·로비 복귀, 다른 플레이어의 세션 지속.
- 빈 전장 재사용 시 초기 재화와 새 세션 생성. 시간 초과·승리도 로비 복귀.
- 단위/통합 테스트로 중복 배정·입장 실패·접속 종료·청크 티켓 해제·메뉴 중복 클릭 검사.

검증 플러그인은 `benchmarks/lobby`에 있으며 제품 JAR에는 포함되지 않습니다. 실제 Minecraft 화면 렌더링 검증은 별도입니다. 과거 20세션 320 TPS 측정에는 이번 로비와 자동 복귀 변경이 포함되지 않았습니다.
