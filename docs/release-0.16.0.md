# 0.16.0 — 세션을 보존하는 전용 리로드

## 사용법

**0.16.0을 처음 설치할 때는 정상 재시작이 한 번 필요합니다.** 현재 실행 중인 0.14~0.15 플러그인에는 이 로더가 없습니다. 일반 /reload, 플러그인 강제 언로드, 서버 재시작은 세션 보존 대상이 아닙니다.

0.16.0부터 MCLuckDefense의 Paper 진입점은 계속 켜 두고 게임 런타임만 교체합니다. 관리자 권한 moma.admin 또는 콘솔에서 사용합니다.

| 명령 | 동작 |
|---|---|
| /mud version | 설치된 로더·현재 게임 런타임·이전 런타임 버전 확인 |
| /mud reload check | 예정 JAR의 호환성 및 실제 세션 복원 검사. 실행 중인 게임은 교체하지 않음 |
| /mud reload | 예정 JAR 적용. 파일이 없으면 현재 런타임을 다시 로드해 설정을 읽음 |
| /mud rollback | 현재 게임 진행도를 보존하면서 이전 런타임 코드로 되돌림 |

업데이트 파일은 **서버의 plugins/update 폴더에 기존 설치 JAR와 같은 이름**으로 둡니다. 현재 라이브 설치명이 mc-luck-defense-0.14.0.jar라면 업데이트 파일도 이 이름을 사용합니다. 내부 버전은 새 버전입니다.

성공한 JAR는 plugins/MCLuckDefense/runtime/cache에 해시별로 보관하며, 동일한 예정 파일은 update 폴더에서 제거합니다. 활성화에 실패해 이전 런타임으로 복구한 파일도 캐시에만 남겨 다음 서버 재시작에 자동 설치되지 않도록 합니다. 업로드 중 파일 내용이 바뀌면 다른 내용은 삭제하지 않고 보존합니다. 호환성 검사 단계에서 거절한 파일은 정상 재시작용 업데이트일 수 있으므로 그대로 둡니다.

Paper 자체의 플러그인 버전 표시는 영구 로더 버전입니다. 핫 업데이트 후 실제 게임 버전은 **/mud version**으로 확인합니다.

## 보존하는 것

- 세션 UUID, 소유자, 전장, 라운드, 준비·진행 시간, 웨이브에서 이미 소환한 위치.
- 소수 골드와 처치 수입, 적 보상 지급 여부, 소환 횟수·초반 보정·선택한 특성.
- 아군과 적의 **기존 엔티티 UUID**. 재소환하지 않으며 배치·강화·계승 공격력·판매 재료값을 보존합니다.
- 적 체력·경로 진행도·감속 만료, 공격 대기시간·연속 공격·공격속도 소수 틱.
- 소환·치명타 난수의 시드, 카운터, 아직 사용하지 않은 해시 블록.
- 세션 배속, 자동판매·자동배치·일괄구매 상태.
- 관전 대상, 모험 모드·플라이·반투명 표시, 종료 시 복구할 플레이어 위치와 모드.
- BGM 타임라인과 리소스팩 적용 상태. 업로드·인증 입력·백그라운드 BGM 작업 중에는 완료 후 다시 시도하도록 거절합니다.

교체는 서버 메인 스레드에서 수행하므로 진행이 잠깐 정지할 수 있습니다. 플러그인의 열린 GUI는 닫고 새 버전에서 다시 열게 합니다. 로비 순위표 같은 화면 요소는 재생성될 수 있습니다. 세션 생성 업적을 다시 세거나 시작 골드를 다시 지급하지 않습니다.

## 호환성·실패 처리

1. 예정 JAR를 복사하고 SHA-256을 확인합니다. 파일명만으로 버전을 신뢰하지 않습니다.
2. 영구 로더, 의존 라이브러리, 플러그인 등록 설정 등 유지되어야 하는 부분을 비교합니다. 달라지면 정상 재시작이 필요합니다.
3. 진행 중인 게임이 있으면 상태 스키마와 등록된 확률·유닛·웨이브 정의가 다른 업데이트를 거절합니다. 기존 세션이 있는 상태에서 새 밸런스를 섞어 적용하지 않습니다.
4. 새 클래스 로더에서 세션을 복원하고, 모든 전투 상태의 필드 값 지문을 비교합니다. 월드·청크·엔티티·소유자·관전 대상의 유효성도 확인합니다.
5. 검증 후에만 기존 리스너·반복 작업·표시 연결을 해제합니다. 새 런타임이 정상 활성화되면 선택 버전을 기록합니다.
6. 새 버전 활성화나 버전 선택 기록에 실패하면 부분 등록을 정리하고 이전 런타임을 다시 활성화합니다. 수동 rollback도 과거 시점의 골드로 되돌리는 기능이 아닙니다.

활성 런타임 선택은 runtime/active.properties에 저장됩니다. **영구 로더 JAR가 그대로인 재시작**에서는 선택한 런타임을 계속 사용합니다. 설치 JAR 자체를 교체한 정상 재시작에서는 새 설치본을 우선합니다. 전투 스냅샷은 런타임 교체용 메모리 데이터이며, 서버 종료·충돌 이후 세션을 복구하는 저장 기능은 아닙니다.

임의의 미래 JAR가 안전하다고 보장하는 기능은 아닙니다. 구조나 의미가 바뀌는 업데이트는 제작자가 상태 스키마를 관리하고 검증해야 합니다. 현재 구현은 호환되지 않는 활성 세션을 여러 버전으로 나눠 동시에 운영하거나 자동 데이터 마이그레이션하지 않습니다. 해당 세션이 끝난 뒤 적용해야 합니다.

## 구현 경계

- MomaPlugin과 bootstrap 패키지는 영구 로더입니다. Bukkit·Paper·의존 라이브러리도 공유합니다.
- 게임 코드와 관련 리소스는 세대별 RuntimeLoader에서 읽습니다. 서버 월드가 계속 참조하는 빈 월드 생성기는 bootstrap에 둡니다.
- GameModule 경계에서는 검증된 스냅샷 바이트로 상태를 전달합니다. 진단용 games 참조는 불투명 객체이며 외부 플러그인용 게임 API가 아닙니다.
- StateCodec은 허용된 내부 데이터만 역직렬화하고 크기·깊이·참조 수를 제한합니다. 플레이어 입력이나 임의의 외부 직렬화 파일은 받지 않습니다.
- 기존 Java 코어 시뮬레이터와 테스트는 그대로 실행됩니다. 내부 클래스를 리플렉션으로 다루는 별도 테스트 플러그인은 현재 런타임의 클래스 로더에서 타입을 해석해야 합니다. benchmarks/reload가 그 예입니다.

## 검증

Maven 테스트 **261개 통과**. 부분 난수 블록과 강화·연속 공격·감속을 포함한 상태를 복제한 뒤 동일한 전투를 진행해 매 틱 필드 지문과 소환 결과가 일치하는지 확인했습니다.

런타임 컨트롤러 테스트는 실제로 다른 코드를 컴파일한 JAR를 로드하여 코드 교체, 검사만 수행, 현재 진행도를 유지한 수동 복귀, 활성화 실패 복구, 버전 선택 파일 쓰기 실패 복구, 호환성 거절, 관리자 권한, 재시작 시 런타임 선택을 검사합니다.

별도 Paper 26.3 서버와 Via 1.21.8 클라이언트 두 개를 사용한 검증:

- 참가자·관전자 연결 및 실제 전투·소환·배속·자동구매 진행.
- 0.16.1-test로 교체하고 새 클래스 로더의 새 메서드 실행 확인.
- 세션 UUID·전투 필드 전체 지문·원래 엔티티·관전 대상·플라이·반투명 표시 유지.
- 비호환 스키마 및 잘못된 BGM 설정 거절.
- 일부 리스너·작업을 등록한 뒤 의도적으로 실패하는 0.16.2-test에서 이전 런타임 복구.
- 수동 rollback, 동일 버전 reload, 열린 이전 GUI 닫기, 세션 생성 업적 중복 방지.
- 반복 교체 후 게임 루프가 하나만 실행되는지 확인.

테스트용 minecraft-data의 1.21.8 더스트 정의가 오래된 float RGB 형식이어서, 클라이언트 fixture에 실제 1.21.8의 packed INT RGB 정의를 지정했습니다. 최종 실행에서는 프로토콜 파싱 경고가 0개였습니다. 이 변경은 테스트 클라이언트에만 적용됩니다.

검증 자료: [실행 결과](runtime-reload-0.16.0/verification.json). 라이브 서버에는 리로드나 재시작을 실행하지 않았습니다.

재현에는 target/mc-luck-defense-0.16.0.jar와 기존 로컬 Paper 라이브러리 폴더가 필요합니다.

~~~powershell
mvn -B -ntp "-Dmaven.compiler.fork=true" test package
python -B scripts/build_reload_fixture.py --plugin target/mc-luck-defense-0.16.0.jar --libraries <Paper-libraries> --output <fixture-directory>
~~~

scripts/run_reload_smoke.py에 별도 서버 JAR, fixture, candidates 디렉터리, 승인된 EULA, Via 플러그인, benchmarks/reload/client.cjs 및 새로운 출력 폴더를 지정합니다. 테스트 서버는 127.0.0.1:25585만 사용합니다.
