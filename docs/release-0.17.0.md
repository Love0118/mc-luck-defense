# 0.17.0 — beta 자동 업데이트

관리자 또는 콘솔에서 **`/mud update`**를 실행하면 공개된 beta 빌드를 다운로드하고 안전 리로드까지 진행한다. 원격 서버에서 소스를 컴파일하지 않는다.

1. `Love0118/mc-luck-defense`의 `beta-latest` 릴리스에서 최신 배포 정보를 읽는다.
2. 해당 커밋의 고정 릴리스에서 JAR를 내려받는다. 다운로드는 별도 스레드에서 수행한다.
3. 크기, SHA-256, JAR 내부 버전·커밋을 검증한다.
4. 서버 메인 스레드에서 기존 리로드 절차로 로더·상태 형식·밸런스·현재 세션 복원을 검증한다.
5. 검증된 런타임으로 교체하고 현재 게임 진행도를 유지한다. 활성화 실패 시 이전 런타임을 다시 활성화한다.

`/mud update check`는 최신 배포 정보만 확인한다. 전체 JAR 검증과 세션 호환성 검사는 실제 `/mud update`에 포함된다. 같은 버전 번호라도 커밋의 JAR 해시가 다르면 업데이트를 검사한다. 이미 같은 파일이면 다운로드·리로드하지 않는다.

**0.16.0 → 0.17.0 최초 설치는 정상 재시작이 한 번 필요하다.** 영구 로더에 업데이트 관리 기능을 추가했기 때문이다. 자동 업데이트 명령은 서버를 재시작하지 않는다. 이후에도 영구 로더·의존성·플러그인 메타데이터가 달라졌거나 활성 세션과 호환되지 않는 빌드는 적용하지 않고 이유를 표시한다.

실패하거나 호환되지 않는 자동 다운로드를 Paper `plugins/update`에 넣지 않는다. 따라서 해당 파일이 나중의 서버 재시작 때 몰래 적용되지 않는다. 수동으로 올린 다른 업데이트 파일이 있으면 덮어쓰지 않고 중단한다. 정상 적용된 런타임은 기존 캐시·활성 버전 기록을 사용하며 `/mud rollback`으로 현재 진행도를 유지하면서 이전 코드로 복귀할 수 있다.

중복 실행을 막으며 자동 업데이트 중 수동 `reload`·`rollback`은 거절한다. 다운로드에는 접속·읽기 시간 제한, 최대 64 MiB 제한, HTTPS 및 GitHub 다운로드 호스트 제한을 적용한다. 관리자 권한 `moma.admin`이 필요하다. 개인 GitHub 토큰을 서버에 저장하지 않는다.

## beta 배포

GitHub Actions는 beta push 후 테스트와 기존 시뮬레이션 스모크가 성공해야 `beta-build-<전체 커밋 SHA>` prerelease에 JAR 및 배포 정보를 게시한다. `beta-latest/update.properties`는 최신으로 게시된 빌드를 가리킨다. CI가 실패하거나 아직 진행 중인 커밋은 자동 배포 대상이 아니다.

배포 작업은 직렬화하고 오래된 커밋의 뒤늦은 게시를 건너뛴다. 이미 게시된 커밋은 재실행해도 기존 JAR를 재사용한다. 포인터 교체 순간의 일시적인 다운로드 실패는 기존 런타임에 영향을 주지 않는다. 잠시 후 명령을 다시 실행하면 된다.

기존 CI에서 발생하던 동일 JVM의 테스트 컴파일 오류는 Maven 컴파일러를 별도 프로세스로 실행하도록 수정했다.

GitHub 배포 파일 형식의 기반: [GitHub Releases API](https://docs.github.com/en/rest/releases/releases).

## 검증 및 설치 준비

- 로컬 Maven 테스트 269개 통과. 해시·크기·커밋·버전 불일치, 중복 실행, 권한, 다운로드 실패, 종료 중 콜백, 호환성 거절, 실제 런타임 교체 및 활성화 실패 복구를 검사했다.
- [beta CI](https://github.com/Love0118/mc-luck-defense/actions/runs/35629283123)에서 Linux 빌드·테스트·시뮬레이션 스모크 및 릴리스 게시 성공.
- 실제 `BetaFeed` 코드로 공개 피드를 읽고 릴리스 JAR를 다운로드하여 SHA-256·내부 버전·커밋 검증 성공.
- 게시된 `70d34b7b` 빌드를 로컬 및 semion의 update 폴더에 배치했다. SHA-256은 `908e50061530f1012315a6afdf1c9dcf8b8136d9e0672a865fed7453bb4a302a`다.
- 이후 사용자의 명시적인 승인으로 semion을 정상 재시작하여 0.17.0을 적용했다. 로컬 Windows 서버는 update 폴더에 준비한 상태다. 라이브 게임 접속 테스트는 실행하지 않았다.
